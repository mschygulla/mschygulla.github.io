# Workflow for Creating New Posts

This document outlines the standard process for authoring and publishing new blog posts using Hugo and GitHub Pages.

---

## Steps

### 1. Create a New Post

Run the following command to scaffold a new post with the default archetype. Replace `name-of-post` with a descriptive, hyphen-separated slug for the post.

```bash
hugo new posts/name-of-post.md
```

This generates a new Markdown file under `content/posts/` with pre-populated front matter (title, date, draft status, etc.).

---

### 2. Author the Post Content

Open the newly created file at `content/posts/name-of-post.md` and write the post content in Markdown. Update the front matter fields as needed — for example, set the `title`, add relevant `tags`, and fill in any other metadata supported by the theme.

---

### 3. Preview Changes in Real Time

Start the local Hugo development server with draft posts enabled:

```bash
hugo server -D
```

Navigate to [http://localhost:1313/](http://localhost:1313/) in your browser to preview the site. The server watches for file changes and reloads automatically, allowing you to review formatting and layout before publishing.

---

### 4. Promote the Post from Draft to Published

Once the post is ready for publication, open its front matter and change the `draft` field from `true` to `false`:

```yaml
draft: false
```

This ensures the post is included in the production build generated by Hugo.

---

### 5. Commit and Push Changes to the Repository

Stage all modified files, create a descriptive commit, and push the changes to the remote repository:

```bash
git add .
git commit -m "Add new post: name-of-post"
git push
```

Use a clear and concise commit message that reflects the content of the post.

---

### 6. Automated Publishing via GitHub Actions

Pushing to the main branch triggers the configured GitHub Actions workflow, which builds the Hugo site and deploys the output to GitHub Pages automatically. No manual deployment steps are required.
